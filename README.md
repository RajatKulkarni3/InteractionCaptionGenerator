# InteractionCaptionGenerator

> **Real-time Human-Object Interaction (HOI) and Object Affordance recognition from a live webcam stream.**

Combines pose estimation, open-vocabulary object detection, a temporal interaction engine, and a trained Random Forest classifier to recognise multi-label object affordances (e.g. *pourable*, *cuttable*) and interactions — frame by frame — and overlay them as on-screen captions.

## Features

- **17-keypoint pose estimation** via YOLO11-Pose — standing, sitting, crouching, lying, jumping, running
- **Open-vocabulary object detection** via YOLO-World — not limited to 80 COCO classes
- **Temporal interaction engine** — tracks how long keypoints stay in contact with objects across frames
- **Rule-based action detectors** — Drinking, Using Phone, Using Laptop, Reading (with tunable temporal thresholds)
- **Multi-label affordance classifier** — Random Forest trained on fused CAD-120 + VidHOI features
- **Live HUD overlay** — posture, natural-language sentence, confidence %, and explainable bullet points

**Sample output:**

```
Posture: sitting  (100% stable)
Person is sitting and drinking while using phone.  [87%]
  - Bottle in contact (2.1s)
  - Hand moved toward the bottle
  - Phone nearby (45px)
```

## Architecture

```
Webcam frame
     │
     ├──▶ YOLO11-Pose ─────────────────▶ 17 named keypoints
     │       (pose_estimation.py)           + PersonPose dataclass
     │                                      + PostureClassifier
     │
     ├──▶ YOLO-World ──────────────────▶ object detections
     │       (object_detection.py)         [{object, confidence, bbox}]
     │
     ├──▶ InteractionEngine ───────────▶ InteractionEvents (fired rules)
     │       (interaction_engine.py)       + ProximityLog (distances + durations)
     │        - ObjectTracker (IoU matching)
     │        - DurationTracker (per keypoint × object timers)
     │        - detect_drinking / detect_using_phone / etc.
     │
     ├──▶ RF Classifier ───────────────▶ predicted multi-label affordances
     │       (models/cad_model.joblib)
     │
     └──▶ build_explanation() ─────────▶ action, reasons[], confidence
             (main.py)                     displayed on frame via HUD overlay
```

**Priority logic:** The interaction engine owns temporal evidence (how long an object has been in contact with a keypoint), which the single-frame RF structurally cannot replicate. The engine always wins when it fires; the RF fills in while temporal evidence is still building.

## Setup & Installation

### Prerequisites

| Requirement | Notes |
|---|---|
| **Python** | 3.10 or higher |
| **Webcam** | For the live pipeline |
| **GPU** | Recommended for real-time speed (CPU works but may lag) |
| **Git LFS** | Model weights are tracked with Git LFS |

### 1. Clone the repository

```bash
git clone https://github.com/RajatKulkarni3/InteractionCaptionGenerator.git
cd InteractionCaptionGenerator
```

### 2. Create a virtual environment (recommended)

```bash
python -m venv venv
# Windows
venv\Scripts\activate
# macOS / Linux
source venv/bin/activate
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Download model weights

Place these files in the `models/` directory:

| File | How to get it |
|---|---|
| `yolo11n-pose.pt` | Auto-downloads on first use: `from ultralytics import YOLO; YOLO("yolo11n-pose.pt")` |
| `yolo_world.pt` | `from ultralytics import YOLOWorld; YOLOWorld("yolov8s-worldv2.pt")` then move to `models/` |

The `cad_model.joblib` classifier is generated automatically by `training/train.py` (see [Training](#training-your-own-model)).

## Running the Project

### Live webcam demo

```bash
python src/main.py
```

Press **Q** or **Esc** to stop.

**On-screen overlay:**

| Colour | Information |
|---|---|
| Red (top-left) | Posture label + rolling stability % |
| Green (bold) | Action label + confidence % |
| Green (bullets) | Up to 3 human-readable reasons |
| Orange boxes | Detected objects with class + confidence |

### Smoke test (no webcam needed)

```bash
python test_pipeline.py
```

Runs all four pipeline stages on a single static image.

## Training Your Own Model

### Step 1 — Extract features from CAD-120

```bash
python training/cad_feature_extraction.py
```

### Step 2 (optional) — Extract features from VidHOI

```bash
# First, set up the VidHOI dataset
python setup_vidhoi.py

# Then extract features
python training/vidhoi_feature_extraction.py
```

### Step 3 (optional) — Extract features from an image dataset

```bash
python training/feature_extraction.py \
    --dataset_root /path/to/your/image/dataset \
    --out outputs/features.csv
```

### Step 4 — Train the classifier

```bash
python training/train.py --features outputs/cad_features.csv
```

Outputs:
- `models/cad_model.joblib` — trained model bundle
- `outputs/evaluation_report.txt` — accuracy, per-class F1, confusion matrix

## Key Design Decisions

| Decision | Rationale |
|---|---|
| **Point-to-box distance** (not center-to-center) | Returns `0.0` when a keypoint is *inside* the box — the correct "touching" signal |
| **Scale-invariant thresholds** | All proximity thresholds are fractions of `bbox_height`, making them invariant to camera distance |
| **Two confidence thresholds** | `0.5` for posture (strict), `0.3` for interaction keypoints (lenient — held objects partially occlude the wrist) |
| **FAR_SENTINEL = 999.0** | Missing features use a large finite value so decision-tree splits work cleanly |
| **Rule engine > RF** | Temporal evidence always trumps instantaneous geometry |
| **IoU-based tracking** | Stable `track_id`s across frames — no GPU MOT tracker needed for single-camera scenes |
| **Rolling feature buffer** | 150-frame `deque` (~5 s) aligns live single-frame inference with video-aggregated training features |
| **Duration grace period** | 10-frame grace window prevents natural YOLO flicker from resetting multi-second timers |

## Known Limitations

- **Single person only** — tracks the largest detected person per frame
- **Rolling buffer warm-up** — predictions may fluctuate during the first ~5 seconds
- **Object detection runs every 2 frames** — speed trade-off; fast-moving objects may be missed
- **Camera angle sensitivity** — posture classification uses fixed geometric thresholds
- **Four rule detectors only** — new actions require writing a new detector in `interaction_engine.py`
- **Dataset alignment** — the RF relies on wrist/face-to-object geometry; generic datasets without props yield poor performance
